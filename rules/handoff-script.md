# 実行できない手順はスクリプトにして渡す

エージェントが自分で実行できない手順がある。対話入力が要るもの（マスターパスワード・2 段階認証）、安全判定で止められるもの（シェル起動ファイルへの書き込み・資格情報の投入）、ルールでユーザーに残してあるもの。こういうとき、長いワンライナーを貼ってもらうのではなく、**1 本のシェルスクリプトを作業用の一時ディレクトリに書き、絶対パスを 1 行で渡して、ユーザー自身の端末で実行してもらい、出力を貼り戻してもらう**。読み手は出力を見るだけで、どこまで通ったかが分かる。

## スクリプトの作り方

- `set -euo pipefail`。手順ごとに `[1/4] 何をするか` と `✔` / `✘` を出し、最初の失敗で止めて次に何をすべきかを書く
- **前提条件を先に全部確かめてから書き込む**。クリップボードの先頭文字列、キーチェーンの項目の有無、アンカー行がちょうど 1 つあること。1 つでも外れたら何も変えずに終わる
- **元ファイルをその場で上書きしない**。`mktemp` に生成し、空でないことを確かめてから `mv` で置き換える。`cp f f.bak; tool f.bak > f` は tool が失敗した時点で `f` が空になるので使わない
- 冪等にする。もう入っていれば「設定済み。スキップ」で通す。ユーザーは失敗後に同じコマンドをもう一度打つ
- macOS の `awk` は `-v` に改行入りの文字列を渡せない。複数行の挿入は `python3 -I` か `perl` のヒアドキュメントで書く
- **秘密の値は出力しない**。`pbpaste` やキーチェーンからスクリプト内で読み、表示するのは文字数と先頭の種別だけ。貼り戻してもらう出力に秘密が混ざらないようにする
- 置き場所は作業用の一時ディレクトリ。リポジトリには入れない。渡すのは絶対パス 1 行

## 渡したあと

- 出力の `✔` を信用せず、読み取り専用の確認で裏を取る（ファイルの diff、`bw status`、workflow の実行結果）
- Claude Code の `!` 前置は対話入力を受け付けない。隠し入力を求めるコマンドは「ご自身のターミナルで」と明示する
- 一度うまくいった手順は、次回のためにそのプロジェクトの docs かスキルに残すかを判断する。マシン固有ならマシン設定リポジトリ、汎用なら ai-rules
