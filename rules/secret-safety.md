# シークレット検知で止まったとき

pre-commit や CI の gitleaks が止めたときに、**ゲートを無効化する方向へ逃げない**。検知は「コミットさせない」ことに価値があり、回避した時点で仕組みごと意味を失う。

## やってはいけないこと

- **`--no-verify` で hook を飛ばさない。** フックの失敗に対して最初に取りがちな行動だが、これを一度やるとゲートが無い状態と同じになる
- **検知された値をそのままコミットして、あとで消す前提にしない。** git の履歴からは消えない。HEAD から消しても残る
- **`--redact` を外さない。** 外すと検知した値がターミナル履歴と CI ログに残り、二次露出になる

## 正しい順番

1. **本当に秘密かを確かめる。** 公開前提の識別子（リソース ID、ブラウザに配信されるトークン、ドキュメント ID）や、テストのダミー値は秘密ではない
2. **秘密なら、まず値を無効化する。** 発行元で再発行・削除してから、コードを環境変数やシークレットストア参照に直す。除外の判断はその後
3. **秘密でないと言い切れるときだけ除外する。** `.gitleaksignore` に fingerprint（`commit:file:rule:line`）単位で書き、**なぜ秘密でないかを必ず併記する**。理由を書けないものは除外しない
4. **無効化できない・実体を特定できないものを除外するときは、そう書く。** 「追跡を打ち切った」と分かる形で残せば、あとから再開できる

fingerprint は行単位なので、同じファイルに新しく入った値は引き続き検知される。ファイル単位やルール単位で無効化しない。

## 検知されない種別を見つけたら

既定ルールは万能ではない（例: `sk-ant-` で始まる Anthropic のキーは既定では検知されない）。扱っている鍵種別が素通りすると分かったら、`.gitleaks.toml` に `[extend] useDefault = true` を維持したままルールを足す。既定ルールを置き換えない。
