# スキル・ルールの置き場所判断

スキルやルールを**新しく作るとき・大きく育てたとき**は、書き始める前に置き場所を判断する。知見は上の層へ集約するほど再利用され、リポジトリに死蔵するほど腐る。

## 4 層と判断基準

| 層 | 置き場所 | 判断基準 |
|---|---|---|
| 外部由来 | skills CLI の台帳（mac-setup 等） | 他人の配布物。改変せずブックマークとして導入する |
| 汎用 | `sugurutakahashi-1234/ai-rules` | 会社名・ブランド・社内システムへの依存が本文に**一切ない**。他社業務でもそのまま使える |
| 会社固有 | 会社のルールリポ（例: `<org>/<org>-ai-rules`） | 会社のブランド・テーマ・製品・社内運用に依存する。ただし複数リポで使う |
| リポ固有 | そのリポの `.rulesync/skills/` / `.rulesync/rules/` | そのリポの構成・スクリプトに密結合。まずはここから始めてよい |

## 運用ルール

- **迷ったらリポ固有から始める**。ただし作ったスキルに会社名依存が無いなら、最初から汎用層に書くことを検討する
- **同じスキルを 2 つめのリポにコピーしたくなった瞬間が昇格のサイン**。コピーせず、上の層へ移して両方から `rulesync.jsonc` の `sources` で参照する
- 昇格の手順: 上の層のリポへ本文と同梱ファイルを移す → 新しいタグを切る → 各リポの `rulesync.jsonc` の `skills` 選定に追加してローカルコピーを削除 → `sync-agents`
- 汎用層に置くときは会社依存箇所（ブランド名・URL・テーマ・社内用語）を汎用化してから移す。汎用化できない部分は会社層に分離する
- 外部由来のスキルを取り込むときは frontmatter の license / 出典を保持し、本文冒頭にも出典を 1 行残す（生成ツールが frontmatter のメタデータを落とすことがあるため）
- AI エージェントは、ユーザーからスキル作成を依頼されたら**どの層に置くかを判断して提案する**こと。汎用層・会社層に置く場合は該当リポジトリでの作業になる旨を伝える

## 教訓の反映（フィードバックをスキルへ継ぎ足す）

作業中に得た教訓・ユーザーからのフィードバックは、**別のメモに溜めず、行動が変わるべきスキル/ルールの該当セクションへ直接反映**する。別ファイルの lessons メモはエージェントに読まれず腐る。

- 本文は**「現在の正」を上書きする形**で書き、時系列ログにしない。経緯は git とタグが持っている
- 日付を書き添えるのは「日付自体に意味がある教訓」だけ（課金方針・外部仕様など、時間経過で前提が変わりうるもの）
- 反映先の層は上の 4 層判断と同じ: 汎用の教訓 → 汎用層のスキルを直して新タグ / 会社固有 → 会社層 / そのリポだけ → そのリポの main.md かローカルスキル
- AI エージェントは、ユーザーのフィードバックが再利用可能な教訓だと判断したら「この教訓を○層の△スキルへ反映しますか？」と**提案する**こと（勝手にコミットはしない）
