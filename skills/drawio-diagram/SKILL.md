# drawio-diagram Skill（編集可能な図をスライドへ埋め込む）

> **Core Principle**: `.drawio` を編集可能な正本、`.svg` を Marp へ埋め込む生成物として同じディレクトリへ置く。
> 図はスライドの補助素材であり、図だけでページの主張と読む順序が分かる状態にする。
> commit / push はユーザーの明示指示があるまでしない。

## Mermaid との関係（原則draw.io）

- **スライドと公開HTMLページへ載せる図は原則すべてdraw.ioで作る**: 構成図・アーキテクチャ図・関係図など「境界・配置」の図に加え、標準的なフロー、Yes / No分岐、手順、シーケンス、時系列など「流れ」の図も本スキルで作る。該当するなら明示依頼を待たず積極的に使う
- **例外: HTMLページの「並べるだけの図」はHTML/CSSで組む**。横N カラムの比較・縦のリスト・2枚の対比のように、矢印を全部消しても意味が通る図は、画像にせず原稿内でHTML/CSSにする（狭い画面で1カラムへ折り返せる・テキストが選択できる・文言修正にCLI書き出しが要らない）。矢印が交差／分岐／合流する図と、2次元の配置自体に意味がある図がdraw.ioの担当。スライドは版面が固定なのでこの例外は適用しない
- **Mermaidは原則使わない**（ユーザー確認済みの方針）: 使うのはユーザーが明示的にMermaidを指定した場合だけ。既存の`.mmd`図は編集の機会にdraw.ioへ置き換え、`.mmd`と`mermaid-config.json`を削除する。同じ情報をMermaidとdraw.ioの両方で管理しない
- draw.io図は生成画像の挿絵ではなく構造図として扱うため、明示的な挿絵依頼は不要。ただしスライド全体へ機械的に増やさない

## 保存場所

`.drawio`正本と`.svg`生成物の2ファイルを、掲載先に応じたディレクトリへ必ず対で保存する。

```text
# 公開スライド（slides/）用
assets/slides/<デッキ slug>/<図名>.drawio
assets/slides/<デッキ slug>/<図名>.svg

# 公開HTMLページ（htmls/）用
assets/htmls/<原稿 slug>/<図名>.drawio
assets/htmls/<原稿 slug>/<図名>.svg

# ブログ記事（src/content/blog/）用
assets/blogs/<記事 slug>/<図名>.drawio
assets/blogs/<記事 slug>/<図名>.svg
```

- `.drawio`だけ、またはSVGだけを残さない。修正可能性とビルド再現性の両方を保つ
- ブログ記事でクロスポストを想定する場合は PNG 書き出しも対で置く（該当リポジトリのブログスキル参照）
- `images/`へ置かない。draw.io図は個別デッキ・個別ページの制作素材であり、生成画像素材（images/）の対象ではない
- ファイル名は内容が分かる英語ケバブケースにする

## 作成ワークフロー

1. **図の目的を1文にする**: 読者に理解させる順序・境界・依存関係を決める。装飾目的なら作らない
2. **掲載先に合わせて設計する**:
   - スライド → **横長**。`references/slide-layout.md` を読み、16:9スライドの本文領域へ収まる構図・文字量にする
   - HTMLページ → キャンバス幅**920px前後**。縦に伸びるのは構わない（ページはスクロールする）ので、手順やフローは縦方向へ素直に並べてよい。実表示は約808pxへ縮むため、最小フォントは13px以上にする
3. **正本を作る**:
   - 標準図をdraw.ioへ持ち込みたい場合は、一時的なMermaidからdraw.io Desktop CLIでXMLへ変換してよい
   - 精密配置や固有シェイプが必要なら`.drawio` XMLを直接作る。手書きする前に`references/xml-authoring.md`を読む
   - 既存`.drawio`の軽微な修正は、対象セルだけを編集してレイアウト全体を壊さない
4. **SVGを書き出す**: 同梱の`bash scripts/export-slide-svg.sh <input.drawio> <output.svg>`を使う
5. **図単体を目視する**: 同梱の`bash scripts/export-check-png.sh <input.drawio> <確認用.png>`で確認用PNGを一時ディレクトリへ出し、構図・文字・接続線をチェックする
6. **掲載先へ埋め込む**:
   - Marp → 通常は `![w:960](../assets/slides/<デッキ slug>/<図名>.svg)`。結論文と同居する場合は`w:900`以下から調整する
   - HTMLページ → リポジトリの資産規約に従ったパスで`<img>`参照する。枠は付けず、狭い画面は横スクロールへ逃がす（CSS の作法は HTML 系媒体スキルの規約に従う）
7. **ページ側で検証する**: `bun run ci`を通し、掲載先を目視する
   - スライド → `dist/slides/<デッキ>.pdf`の該当ページ（例: `pdftoppm -f <頁> -l <頁> -r 100 -png dist/slides/<デッキ>.pdf <出力先>`でPNG化して確認）
   - HTMLページ → そのリポジトリのプレビュー手順で開き、**デスクトップ幅と狭い幅の両方**で文字が読めること・ページ本体が横スクロールしないことを確認する

## draw.io Desktop CLI

macOSでは次の順で実行ファイルを探す。同梱スクリプトが同じ順序で解決する。

1. `drawio`（PATH）
2. `draw.io`（PATH）
3. `/Applications/draw.io.app/Contents/MacOS/draw.io`

スライド用SVGには編集データを埋め込む`-e`を付けない。編集可能な`.drawio`正本を別に保持する方が、SVGを小さく保ち、正本と生成物の役割も明確になる。

```bash
/Applications/draw.io.app/Contents/MacOS/draw.io \
  -x -f svg -b 10 \
  -o assets/slides/<デッキ slug>/<図名>.svg \
  assets/slides/<デッキ slug>/<図名>.drawio
```

- `--layout`はdraw.io Desktopの版によって未対応なので、版を確認せず使わない
- CLIがない場合も`.drawio` XMLまでは作れる。SVG出力が必要ならユーザーへDesktop導入を依頼し、未検証の生成物を確定扱いしない
- コマンドが落ちる環境では連続リトライせず、Desktop GUIで開ける`.drawio`を残して状況を伝える

## 見た目の自己チェック

SVG生成後、対象ページをPNGへ変換して開き、最大2回まで修正する。

- 図全体がページ内に収まり、端が切れていない
- 最小文字が投影時にも読める。ラベルを詰めず、必要なら図を分割する
- 接続線が無関係なノードやラベルを横切らない
- 矢印の向き、境界、親子関係が一意に読める
- 白背景・枠・影を重ねず、SVG自体をスライド背景へ直接置く
- 色だけで意味を伝えず、ラベル・形でも区別する
- **点線・破線を使わない**（破線の枠も破線の矢印も）。補助的に見せたい要素は線種ではなく、塗りの薄さ・文字色・余白で差をつける
- **左右で対になるブロックは同じ幅・同じ高さに揃える**。片側だけ広いと余白がちぐはぐになり、左右の対応関係が読み取りにくくなる
- **白余白をたっぷり取る**。ノードや文字をキャンバスの端・コンテナの枠に詰めない（キャンバス外周 24px 以上、コンテナ枠と中身の間 16px 以上が目安）。余白が少ない図は縮小表示で一気に窮屈になる
- **意味を持たない装飾の枠を描かない**。特に「図全体を包むだけの大きな灰色角丸コンテナ」は情報がないのに面積と視線を奪うのでやめる。コンテナを使うのは境界そのものに意味がある場合（システム境界・ネットワーク境界・所有権の範囲など）だけで、塗りは白 + 細線を基本にし、灰色塗りは多層ネストの内側 1 層までに抑える。単なるグルーピングは枠ではなくラベル + 余白で示す
- **図の中に複数行の説明文を書かない**。図中のテキストはノードのラベル・矢印のラベル・凡例と、置くとしても**1 行で収まる結論・キーメッセージ 1 本**（下部など）まで。背景・理由・補足のだらだらした説明パラグラフを図に入れると図解としての一覧性が死ぬ。細かい説明は掲載先に寄せる（HTML ページなら本文の段落・キャプション、スライドなら本文）。図は「構造と流れが一目で分かる」ことだけに専念させる
- **結論・キーメッセージは素のテキストで置かず「ヒント風ピル」にする**。図の下部中央に、📌 を先頭に付けた**淡い黄のピル**で置く（`rounded=1;arcSize=50;fillColor=#fff8c5;strokeColor=#d4a72c;fontColor=#1f2328;fontStyle=1;fontSize=15;` 高さ 42px 目安。絵文字は背景と同系色を避ける — 💡 は黄背景に沈むので使わない）。素の太字テキストだと図の一部なのか結論なのか区別が付かず、逆に濃色（紺・黒）の帯は重すぎる。**横幅いっぱいの帯にはしない** — 視界がぼやけるので、テキスト内容に合わせた幅（600〜680px 目安）で中央配置する。**中央の基準は「キャンバス」ではなく「図の実内容（全要素のバウンディングボックス）」**。SVG 書き出しは余白をトリミングするため、キャンバス中央に置くと実表示でズレる。実内容の左端 x と右端 x から中心を計算してピルの x を決める

図だけを単独表示して良く見えても、タイトル・header・footerを含むMarpページでは切れることがある。必ず最終ページ側で確認する。

## やらないこと

- MarketplaceやMCPを必須依存にしない。ローカルファイルとDesktop CLIだけで再現できる状態を保つ
- 実行時にdraw.ioや外部CDNを読み込むHTMLを公開スライドへ埋め込まない
- `.drawio`とSVGを別ディレクトリへ分散させない
- 図を直すためにデッキ内へ自前CSSを追加しない
- 生成後にdraw.io Desktopを勝手に開かない。ユーザーへ絶対パスを提示する
