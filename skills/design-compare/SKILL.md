# design-compare Skill（デザイン案の比較モックを出して選んでもらう）

> **Core Principle**: 案は言葉で説明するより、**差が見える 1 枚のモックに並べて選んでもらう**。
> 完璧な再現は不要 — 「この差でどれがいいか」を判断できる最小のモックでよい。
> 作り込みに時間をかけず、案出しの一部として素早く出す。

## いつ使うか

- デザイン・スタイルの変更案を 2 つ以上出すとき（ユーザーの明示依頼がなくても原則出す）
- 使わない場面: 案が 1 つしかないとき・見た目に差が出ない変更（コピー文言だけの修正など）
- 案が決まった後の実装の見た目確認は本スキルの範囲外。そのリポジトリの UI 確認規約（Storybook 等）に従う（比較モックはその前段の案選び専用）

## 比較ページの作り方

1. **置き場所はセッションの scratchpad**。公開物ではないのでリポジトリ内に置かない（scratchpad が無い実行環境でだけ `.tmp/design-compare/` を使う）。
   ファイル名は `design-compare-<topic>.html`
2. self-contained な単一 HTML・`lang="ja"`。外部 CDN・外部フォントは使わない
3. **実物の値を使う**。色・フォントサイズ・不透明度・余白は対象実装から読み取った実値を使い、
   表示テキストも実ページの実データを使う（ダミー文字は折り返しや密度の判断を誤らせる）
4. ページ構成:
   - 冒頭に H1 + 前提の 1 行（どのページのどの部分か・全案共通の変更があるならそれ）
   - 論点ごとにセクション（H2）を分ける
   - **必ず「現状」を最初に置く**（差のベースライン。現状タグはグレーで区別）
   - 各案 = 案ラベル（案A / 案B…）+ 何を変えたか 1 行 + モック。推し案には「推し」バッジ
   - 案は**縦に並べる**。横並びのグリッドは幅が実寸にならず、折り返し・密度の差が見えなくなる
   - 論点が複数あるときは、最後に**推し案を全部適用した「全部入りプレビュー」**を置く
5. モックの幅・背景・角丸は実物に合わせる（対象実装の CSS 変数・Tailwind クラスから実値を読み取り、ダーク面の案なら実際の背景色のパネルに載せる）
6. ブラウザ依存の CSS（`word-break: auto-phrase` など）を使う案には、対応状況をバッジで明記する
7. 案の数は 1 論点あたり 3〜5 個を目安にする（2 個なら差分説明で足りることが多く、6 個以上は選べない）

## 提示の仕方

- 比較ページは **`open` で開いてよい**（他の成果物は「パス提示のみ」が原則だが、比較ページは例外とするユーザー許可済み）。あわせてフルパスも提示する
- (Claude Code のみ) SendUserFile（display: render）でも送り、サイドパネルでも見られるようにする
- 見た目に出ない差（実装コスト・保守性・レスポンシブ対応への影響など）はチャット側の説明で補足する
- ユーザーが案を選んだら実装に進む。比較ページは使い捨てで、commit しない
